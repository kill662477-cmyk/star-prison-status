# 매시간 갱신 계획

최초 전체 조회 결과를 초기 작성자 목록으로 사용. 매 실행 전체 글 재수집하지 않음.

1. GitHub 전용 데이터 브랜치에서 작성자 회원번호 목록과 마지막 정상 수집 글 번호를 읽음.
2. 스타대학·스타감옥 현재 밴 목록은 모든 페이지 확인. 새 밴뿐 아니라 해제도 반영해야 하므로 첫 페이지만 보지 않음.
3. 스타감옥 최신 일반 글부터 역순 조회. 기존 확인 글 번호 이하까지 도달하면 종료. 공지글은 중단 기준에서 제외하고, 경계 페이지는 여유 있게 재확인.
4. 새 작성자 회원번호와 근거 글 주소를 누적 저장. 작성 이력은 유지. 닉네임은 회원번호로 연결하며 현재 밴 목록의 닉네임 사용.
5. 현재 스타대학 밴 AND 스타감옥 작성 이력 AND 현재 스타감옥 밴 아님 조건으로 현황 계산.
6. 등록일+밴기간으로 출소 예정일 계산. 원본 남은 시간과 검증. 한국시간 기준 D-day 갱신.
7. 표시 데이터 변경 시에만 캡처·고정 이미지 교체. 기준 시각을 이미지에 매번 표시하기로 결정하면 매시간 캡처.
8. 수집·검증 성공 후 작성자 목록과 확인 지점 저장. 실패한 수집으로 확인 지점을 전진시키거나 밴 해제로 간주하지 않음.

한 번에 한 실행만 진행하도록 구성. GitHub 데이터 브랜치는 앱 배포와 분리하고 Vercel 빌드 트리거도 분리 설정 확인. 앱 배포 없이 현황 데이터와 고정 이미지가 갱신되는 저장·조회 구조 사용. 배포·자동화 구현은 아직 진행하지 않음.

최초 수집은 시점이 다른 페이지 묶음이므로 최초 운영 실행 때 최신 페이지부터 다시 확인. 이후 오래된 삭제 글을 재조회해 작성 이력을 지우지 않음. 게시판 이전 등으로 오래된 글이 뒤늦게 유입되는 예외는 별도 재수집으로 처리.
